# انتشار هدایت‌شده — بازسازی فاز ۶

این سند جایگزین جریان قدیمیِ محدود به Node.js روی سرویس موجود است. فاز ۷ آغاز نشده است.

## مسیر کاربر

در گفتگو درخواست انتشار یا لینک پروژه را وارد کنید. ویزارد داخل همان گفتگو باز می‌شود: مخزن ← ورود GitHub فقط در صورت نیاز ← انتخاب یا جستجوی شاخه ← بررسی زنده ← انتخاب بخش پروژه هنگام ابهام ← پیشنهاد منابع حساب لیارا ← اتصال امن حساب در همان پنجره در صورت نیاز ← پلن و نام سرویس جدید یا مقصد موجود ← تنظیمات محرمانه ← مرور هزینه و اثر عملیات ← تأیید اختصاصی ← اجرای واقعی و تایم‌لاین ← بررسی HTTP و ذخیره نتیجه.

پرسش‌های غیرمحرمانه مدل با ابزار strict `ask_user` به فرم متناسب تبدیل می‌شوند. پاسخ فرم، بعد از اعتبارسنجی گزینه‌ها و مالکیت، گفتگو را ادامه می‌دهد. رازها در فرم اتصال و env اختصاصی دریافت می‌شوند و به مدل ارسال نمی‌شوند. انتخاب منابع با اطلاعات واقعی حساب انجام می‌شود؛ انتخاب یک مدل AI به‌معنی اجازه ساخت منبع ابری نیست.

## تشخیص و پلتفرم‌ها

Node.js، Next.js، Laravel، PHP، Python، Django، Flask، .NET، React، Angular، Vue، Static، Go و Docker در رجیستری مشترک ثبت شده‌اند. Express/Fastify/Nest به Node، FastAPI به Python و Symfony به PHP نگاشت می‌شوند. وجود package.json به‌تنهایی بک‌اند را Node معرفی نمی‌کند. برای Laravel، Composer/فایل‌های PHP، و برای Django، وابستگی‌ها/manage.py/WSGI بررسی می‌شوند. ابزار فرانت‌اند با بک‌اند اشتباه نمی‌شود. در چند محیط اجرای مستقل، کاربر مقصد را انتخاب می‌کند.

فرمان‌های صریح liara.json و Procfile، scripts پروژه و فایل ورودی بررسی می‌شوند. دستورهای انتخابی و تنظیمات platformConfig در snapshot ثبت می‌شوند. در حالت مبهم حدس موفقیت نداریم؛ پوشه/فرمان با فرم پرسیده می‌شود. فرمان دلخواه برای پلتفرم‌هایی که چنین مسیری در adapter دارند، با تأیید جداگانه قابل ثبت است. تنظیم start وب‌سرور مدیریت‌شده PHP یا Dockerfile از مسیر فرمان Node جعل نمی‌شود.

برای Laravel، ساخت assets از scripts مرتبط تشخیص داده و platformConfig.buildAssets به لیارا ارسال می‌شود؛ alias لازم production در بسته انتشار آماده می‌شود. React/Vite با خروجی build آماده می‌شود. build.location محل جغرافیایی ساخت است و به‌اشتباه به‌عنوان پوشه خروجی استفاده نمی‌شود. Python فرمان اجرا را از args رسمی دریافت می‌کند. آیکون‌های اصلی ارسالی کاربر در apps/web/public/platforms همراه فهرست منبع نگهداری می‌شوند.

پشتیبانی از یک پلتفرم، تضمین انتشار تمام پیکربندی‌های ممکن آن نیست. Expo/React Native به‌عنوان سایت React تلقی نمی‌شوند. مخزن موبایل پیش از انتخاب روش سازگار وب، آماده انتشار اعلام نمی‌شود.

## بررسی مخزن بزرگ و استریم

POST /repositories/inspections یک بررسی پایدار می‌سازد. وضعیت و رویدادها در PostgreSQL ثبت می‌شوند. GET وضعیت و SSE با کنترل مالکیت در دسترس‌اند؛ پس از قطع اتصال، کلاینت به شناسه همان بررسی برمی‌گردد. lease برای ادامه بررسی قطع‌شده به کار می‌رود؛ این مسیر mutation ابری ندارد.

سقف ۵۰۰ فایل، ۵ مگابایت مجموع و ۲ مگابایت برای فایل عادی از تحلیل حذف شده است. بررسی ابتدا metadata و سپس فایل‌های تنظیمات را می‌خواند، نه تمام تصاویر و باینری‌ها را. اگر tree بازگشتی GitHub truncated باشد، پیمایش پوشه‌ها انجام می‌شود. دریافت فایل‌های تنظیمات و سورس در دسته‌های محدود انجام می‌شود و پیشرفت واقعی منتشر می‌شود. محدودیت upstream، زمان شبکه، مسیر ناامن، symlink/submodule و پیکربندی ناسازگار همچنان ممکن‌اند؛ «نامحدود مطلق و بدون خطا» ادعا نمی‌شود.

ظرفیت انتقال فعلی بسته انتشار در حافظه ۱۲۸ MiB است؛ این سقف بررسی مخزن نیست. فقط فایل‌های پوشه انتخاب‌شده دریافت می‌شوند. سورس‌ها با SHA همان commit بررسی و با tar/gzip بسته می‌شوند؛ کد مخزن روی سرور API اجرا نمی‌شود. فایل‌های حساس در bundle کنار گذاشته می‌شوند.

## حساب خالی، قیمت و پرداخت

پلن‌ها و بسته‌ها از GET رسمی v1/me و شبکه‌ها از v1/networks دریافت می‌شوند. پلن‌های غیرفعال قدیمی که region ندارند، کل کاتالوگ را خراب نمی‌کنند. CPU/RAM/disk و برآورد ماهانه فقط از داده واقعی به دست می‌آید؛ نبود قیمت صریح نمایش داده می‌شود. پیشنهاد RAM یک نقطه شروع بر اساس نوع پروژه است، نه اندازه‌گیری بار واقعی.

داشتن سرویس قبلی شرط نیست. حساب بدون پروژه می‌تواند پلن انتخاب کند و پس از تأیید، شبکه و سرویس جدید بسازد. اگر وضعیت اعتبار حساب دریافت شود و اعتبار کافی برای شروع وجود نداشته باشد، مسیر شارژ رسمی لیارا نمایش داده می‌شود. کلیک روی «برگشتم» اثبات پرداخت نیست: اطلاعات حساب دوباره خوانده می‌شود و پاسخ واقعی لیارا در زمان ساخت ملاک نهایی است. پرداخت در کنسول رسمی انجام می‌شود؛ درگاه بانکی داخلی یا webhook پرداختِ مستندنشدۀ فرضی نداریم. تغییر قیمت/مشخصات پلن تا زمان تأیید/اجرای طرح موجب بازبینی طرح می‌شود.

## تأیید و اجرا

طرح، commit، اتصال و نسخه credential، هویت GitHub خصوصی، مقصد، پلن/بسته، مشخصات و قیمت تأییدشده، شبکه، تنظیمات اجرا، نام envها و hash رمزگذاری‌شده تنظیمات را ثبت می‌کند. تصمیم فقط hash و approve/cancel دارد؛ مالک از نشست تعیین می‌شود. outbox، BullMQ و lease سرویس برای اجرای طرح تأییدشده استفاده می‌شوند. سرویس و env پس از تأیید ایجاد/اعمال می‌شوند؛ سپس upload رسمی، release با پلتفرم درست، انتظار برای همان release و دو HTTP probe انجام می‌شود.

SSE و fallback خواندن وضعیت، رویدادهای واقعی را در همان گفتگو نمایش می‌دهند. HTTP موفق بدون نشانگر فقط دسترسی وب را تأیید می‌کند؛ صحت تمام قابلیت‌های پروژه یا پایش دائمی ادعا نمی‌شود. شکست و پاسخ نامعلوم به موفقیت تبدیل نمی‌شوند. عملیات مبهم خودکار تکرار یا rollback نمی‌شود؛ منبعی که قبل از شکست ساخته شده نیز خودکار حذف نمی‌شود و ممکن است هزینه داشته باشد.

GitHub OAuth با state یک‌بارمصرف، binding مرورگر، PKCE و توکن رمزگذاری‌شده پیاده است. scope استاندارد repo این OAuth از لحاظ مجوز GitHub گسترده است؛ backend بررسی مخزن فقط GET انجام می‌دهد. credential اتصال لیارا و envها در مدل و پاسخ API افشا نمی‌شوند. پس از OAuth، مسیر شروع‌شده از چت به همان گفتگو برمی‌گردد.

## بازیابی انتشار و جلوگیری از تکرار

برای شکست یا نتیجه نامعلوم، «بررسی مجدد وضعیت» ابتدا سرویس و همان شناسه release را از لیارا می‌خواند. انتشار در حال ساخت دوباره ایجاد نمی‌شود؛ در حالت READY، دو بررسی وب برای تأیید نتیجه لازم است. اگر نسخه دیگری فعال باشد، جایگزینی آن به طرح و تأیید تازه نیاز دارد. پاسخ مبهمِ درخواست ساخت یا release مجوز تکرار نیست.

«آماده‌سازی تلاش دوباره» فقط پس از روشن‌شدن نتیجه، همان commit را دوباره بررسی می‌کند و یک طرح PLANNED مرتبط با تلاش قبلی می‌سازد؛ ساخت/بارگذاری/انتشار تا تأیید تازه انجام نمی‌شود. ارسال تکراری این درخواست به همان طرح برمی‌گردد. فرم اصلاح تنظیمات برای ناسازگاری پلتفرم یا داده محرمانه ناقص در دسترس است. خطاهای دریافت GitHub به کد اصلی خود ثبت می‌شوند و دیگر همگی DEPLOYMENT_INCOMPLETE نیستند. مرحله اجرا و heartbeat ذخیره می‌شوند. بررسی‌های خواندنی شبکه، ساخت و سلامت تلاش محدود و قابل مشاهده دارند؛ mutation با نتیجه نامعلوم تکرار خودکار ندارد.

دریافت سورس انتشار از آرشیو commit انجام می‌شود، نه یک درخواست REST به ازای هر فایل. فایل‌های حذف‌شده از آرشیو توسط export-ignore یا تغییرکرده توسط export-subst از URL همان commit بازیابی می‌شوند؛ اندازه و Git blob SHA تمام فایل‌های بسته تأیید می‌شود. مخزن خصوصی احراز هویت دارد و credential به مقصد redirect منتقل نمی‌شود. آرشیو روی سیستم استخراج نمی‌شود. ظرفیت‌های محافظتی انتقال و بازکردن آرشیو همچنان برقرارند.

## انتخاب منابع مطابق کنسول لیارا

جدول انتخاب منابع از تصاویر اصلی سیاره‌ها و نشان بسته‌ها در public/plans استفاده می‌کند: زمین، مریخ، مشتری، زحل، اورانوس، نپتون، پلوتون و بسته‌های پایه، نقره‌ای، طلایی. انتخاب با ستون رنگی و جدول RAM، vCPU، دیسک و قیمت ماهانه/ساعتی انجام می‌شود؛ در موبایل جدول اسکرول افقی مستقل دارد. منابع اضافه موجود در حساب نیز با عنوان مشخص نمایش داده می‌شوند. فقط بسته‌های فعال ارائه می‌شوند. displayPrice رسمی حساب برای قیمت ماهانه اولویت دارد؛ تصویر کاربر مرجع طراحی است و قیمت ثابت از آن وارد نشده است.

## تجربه زنده ایجنت

ترمینال لاگ ساخت cursor همان release را از قرارداد v2 کنسول دریافت می‌کند؛ خروجی ساخت مستقل از پیام وضعیت، هر سه ثانیه تازه می‌شود. رویداد بدون تغییر تکرار نمی‌شود. مدل می‌تواند لاگ و مرحله اجرای متعلق به کاربر را تحلیل و سؤال تکمیلی مطرح کند؛ پیشنهاد تغییر، مجوز اجرا نیست.

نیازسنجی منابع با پنجره تعاملی مدل و پاسخ آزاد انجام می‌شود. مدل از گزینه‌های کاتالوگ واقعی پیشنهاد می‌دهد؛ انتخاب نهایی با کاربر است. حداقل برآورد استاتیک با مصرف واقعی تضمین‌شده یکسان نیست. فایل dotenv در مرورگر تجزیه و سپس فقط از مسیر اختصاصی تنظیمات رمزگذاری‌شده ارسال می‌شود؛ محتوای فایل به مدل ارسال نمی‌شود. نام‌های شناسایی‌شده env لزوماً الزامی نیستند و موارد خالی/اختیاری مانع ساخت طرح نمی‌شوند.
